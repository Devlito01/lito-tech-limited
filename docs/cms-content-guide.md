# CMS Content Guide

Use this guide when you want to add or edit `Insights`, `Projects`, and `Services` in Sanity.

## General rule

Each content type should be filled in a way that is:

- clear
- professional
- easy to scan
- not too wordy

Do not try to make every field long. Short, clear content usually works better.

## 1. Insights posts

Use Insights for:

- articles
- tips
- business ideas
- web design topics
- web app topics
- SEO topics

### Fields

#### Title

The main headline of the article.

Example:

- `How We Built a Smarter Web App for Modern Businesses`

#### Slug

The URL version of the title.

Example:

- `how-we-built-a-smarter-web-app-for-modern-businesses`

#### Category

The topic group for the post.

Examples:

- `Web Apps`
- `Web Design`
- `SEO Content`
- `Business Growth`

#### Excerpt

A short summary shown on the Insights page.

Keep it to one clean sentence.

Example:

- `A look at how our latest web app project helps businesses manage work more clearly and efficiently.`

#### Cover Image

Use an image that matches the article.

Good options:

- project screenshot
- dashboard image
- relevant mockup
- branded illustration

#### Alt Text

Describe the image simply.

Example:

- `Preview of a modern web app dashboard by Lito Tech Limited`

#### Body

This is the full article content.

Good structure:

1. introduction
2. problem
3. solution
4. result

Example:

```text
Our latest web app project was created to help businesses manage their workflow more clearly and efficiently.

Many growing businesses struggle with scattered tasks, unclear communication, and systems that are difficult to use. We wanted to create something simpler, more modern, and easier to work with.

The result is a web app experience focused on clarity, speed, and usability. It is designed to help teams stay organized, reduce friction, and work with more confidence.

Projects like this show that a strong web app can do more than look modern. It can help a business feel more capable, more efficient, and better prepared for growth.
```

## 2. Projects

Use Projects for:

- case studies
- project directions
- portfolio pieces
- work examples

### Fields

#### Title

The name of the project entry.

Example:

- `App-Style Interface for Organizing Tasks and Communication`

#### Slug

The URL version of the title.

Example:

- `app-style-interface-for-organizing-tasks-and-communication`

#### Tag

A short label for the project type.

Examples:

- `Client Workflow Dashboard`
- `Corporate Website Concept`
- `Campaign Landing Experience`

#### Summary

A short overview shown on the Projects page.

Example:

- `This concept explores how a clean digital workspace can make a process feel easier, more credible, and more efficient for both teams and clients.`

#### Cover Image

Use:

- project mockup
- screenshot
- UI preview

#### Alt Text

Example:

- `Preview of a workflow dashboard project by Lito Tech Limited`

#### Industry

The industry or use case.

Examples:

- `Professional Services`
- `Operations / Internal Tools`
- `Marketing / Sales`

#### Focus

A few short focus areas.

Examples:

- `Usability`
- `Structure`
- `Scalability`

#### Body

Use the body to explain the project in more detail.

Good structure:

1. what the project is
2. what problem it solves
3. what makes the solution strong

Example:

```text
This project explores how a modern dashboard can organize tasks, improve communication, and make workflows feel easier for both teams and clients.

The goal is to reduce confusion, improve visibility, and create a cleaner digital experience that feels practical and trustworthy.

Projects like this show how thoughtful interface design can improve both usability and business confidence.
```

## 3. Services

Use Services for the core things your company offers.

### Fields

#### Title

The service name.

Examples:

- `Premium Web Design`
- `Website Development`
- `Web App Development`
- `SEO Writing and Content Structuring`

#### Slug

The URL version of the title.

Example:

- `web-app-development`

#### Description

This is the short service summary shown on the Services page.

Example:

- `For businesses that need more than pages, we create web-based tools and digital workflows that help users interact, manage information, or complete tasks more efficiently.`

#### Cover Image

Use a visual that fits the service.

Examples:

- dashboard mockup
- website screen
- branded UI preview

#### Alt Text

Example:

- `Preview of a web app development service by Lito Tech Limited`

#### Service Items

These are the bullet points shown in the service listing.

Examples:

- `Dashboards and internal tools`
- `Client-facing product interfaces`
- `Interactive forms and digital workflows`
- `Scalable frontend foundations`

#### Body

Use the body to explain the service more clearly.

Good structure:

1. what the service is
2. who it is for
3. why it matters

Example:

```text
Web app development helps businesses move beyond brochure websites into tools and platforms that support real workflows and ongoing use.

It is a strong fit for businesses that need user interaction, dashboards, internal tools, or more advanced digital processes.

The goal is to create web products that feel useful, clear, and ready for growth.
```

## Writing tips for all CMS content

- keep paragraphs short
- avoid repeating the same idea
- avoid vague lines like `we can do anything`
- use simple professional English
- write for clarity before trying to sound impressive

## Simple content formula

If you are unsure what to write, use this formula:

1. what it is
2. what problem it solves
3. why it matters

That works for:

- posts
- projects
- services
