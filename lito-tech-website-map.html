CMS Content Plan

For Lito Tech Limited, the smartest first setup is to use Sanity as a headless CMS for the content that needs regular updates, while keeping the core layout and brand structure coded directly into the website.

What Should Be Managed In Sanity

  • Blog posts and insight articles
  • Projects or portfolio case studies
  • Testimonials
  • Selected service entries and service descriptions
  • Author or team profile details if needed later

Why these belong in the CMS: they are the parts of the website most likely to change over time and are the parts you will want to update without editing code.

What Should Stay Coded At First

  • Homepage layout and section structure
  • Main navigation
  • Footer
  • Brand styling, colors, and motion behavior
  • Fixed call-to-action sections
  • Core trust-building layout blocks

Why these should stay coded: they define the premium visual experience of the site and usually do not need constant editing. Keeping them coded makes the build cleaner, faster, and easier to control.

Recommended Sanity Content Types

  • Post: title, slug, category, cover image, summary, body content, publish date, author, SEO fields
  • Project: project name, slug, client or project type, thumbnail, gallery, challenge, solution, results, technologies, SEO fields
  • Testimonial: client name, role, company, quote, image, featured status
  • Service: service name, slug, short summary, detailed description, benefits, optional icon, SEO fields
  • Author: name, role, bio, profile image, social links

Why Sanity Is A Good Fit

  • It works well with modern custom-built websites.
  • It lets you update important content without touching code.
  • It keeps the design flexible while still giving you an admin dashboard.
  • It is a strong option for a premium company site that may grow later.
  • Its free plan is usually enough for a small company website at the beginning.

Recommended setup summary:

Use Sanity for blog posts, projects, testimonials, and selected service content. Keep the homepage layout, navigation, footer, and brand presentation coded directly into the site for a cleaner and more premium result.

Layout Cheat Sheet

These are practical layout patterns that can be reused in many websites. They are not rules you must memorize perfectly at once. They are common building blocks you can understand, reuse, and adjust.

Common Grid Patterns

  • Two equal columns: grid-template-columns: 1fr 1fr;
  • Two columns, one bigger: grid-template-columns: 1.2fr 0.8fr;
  • Three equal columns: grid-template-columns: repeat(3, 1fr);
  • Four equal columns: grid-template-columns: repeat(4, 1fr);
  • Responsive cards: grid-template-columns: repeat(auto-fit, minmax(250px, 1fr));
  • Mobile stacking: switch to grid-template-columns: 1fr; inside a media query

Common Flexbox Patterns

  • Row layout: display: flex; gap: 1rem;
  • Space between items: display: flex; justify-content: space-between; align-items: center;
  • Centered content: display: flex; justify-content: center; align-items: center;
  • Vertical stack: display: flex; flex-direction: column; gap: 1rem;
  • Wrapping items: display: flex; flex-wrap: wrap; gap: 1rem;

When To Use Each

  • Use Grid for bigger section layouts, page columns, and card systems.
  • Use Flexbox for smaller groups like buttons, nav links, icon-and-text rows, and stacked content.
  • Simple rule: Grid is for larger layout structure, Flexbox is for smaller alignment tasks.

Practical note:

You do not have to invent layout code from your head every time. A professional workflow is to understand the layout goal, use a known pattern, test it, and then adjust the values to fit the website.

Mobile View Patterns

Mobile view is usually handled with CSS media queries. The same website changes its layout when the screen becomes smaller. The exact mobile code is not identical for every website, but the common patterns are very similar.

1. Business or Company Website

Desktop pattern: two-column hero, multi-column services, horizontal navigation

Mobile pattern: one-column hero, stacked cards, menu button instead of full nav

Example code:

@media (max-width: 768px) { .hero-grid, .services-grid { grid-template-columns: 1fr; } .nav-toggle { display: inline-flex; } }

2. Portfolio Website

Desktop pattern: project cards in two or three columns

Mobile pattern: one-column project cards with bigger spacing for readability

Example code:

@media (max-width: 768px) { .project-grid { grid-template-columns: 1fr; } }

3. Blog or News Website

Desktop pattern: main article area with sidebar

Mobile pattern: content stacked into one column, sidebar moved below the main article

Example code:

@media (max-width: 900px) { .content-layout { grid-template-columns: 1fr; } }

4. Ecommerce Website

Desktop pattern: product grids with multiple columns, larger filter areas

Mobile pattern: product cards in one or two columns, filters collapsed into a simple panel

Example code:

@media (max-width: 768px) { .product-grid { grid-template-columns: repeat(2, 1fr); } }

@media (max-width: 520px) { .product-grid { grid-template-columns: 1fr; } }

5. Dashboard or Web App

Desktop pattern: sidebar plus main content area

Mobile pattern: sidebar collapses into a menu drawer and content fills the screen

Example code:

@media (max-width: 900px) { .app-shell { grid-template-columns: 1fr; } .sidebar { position: fixed; transform: translateX(-100%); } }

6. Landing Page

Desktop pattern: wide hero section, side-by-side content, several feature columns

Mobile pattern: stacked sections, centered calls to action, smaller heading sizes

Example code:

@media (max-width: 768px) { .hero h1 { font-size: 2.5rem; } .feature-grid { grid-template-columns: 1fr; } }

Where To Get Mobile Code Patterns

  • From your own past projects: reuse patterns you already understand.
  • From documentation: MDN is excellent for learning CSS Grid, Flexbox, and media queries.
  • From trusted tutorial sites: use examples from CSS-Tricks and similar frontend learning resources.
  • From templates: study how premium templates switch layouts on tablet and mobile.
  • From developer tools: inspect websites and test layouts in browser mobile view.
  • From collaboration: ask for a pattern, understand it, then adapt it to your own design.

How To Choose The Right Mobile Code

  • First ask what the desktop layout is doing.
  • Then decide what must stack, shrink, hide, or become a menu on small screens.
  • Choose a known pattern such as one-column stacking, smaller heading sizes, or a mobile nav drawer.
  • Test the layout and adjust the breakpoint or spacing if needed.

Simple rule:

The mobile version is not a completely separate website. It is usually the same HTML with extra CSS rules that change the layout for smaller screens.

Remaining Work Checklist

The main website structure is built. The remaining work is the final stage that turns the project from built into launch-ready.

1. Final Branding

  • Replace the temporary `LT` brand mark with the final logo
  • Add the final favicon
  • Check brand consistency across all pages

2. Visual Polish

  • Refine spacing and alignment across the site
  • Review heading sizes and typography hierarchy
  • Improve any areas that still feel like placeholders
  • Check consistency between sections and pages

3. Real Content Polish

  • Review all text for clarity and consistency
  • Decide whether project examples remain concepts or become real portfolio entries
  • Decide whether insight titles remain placeholders or become real articles

4. Form Setup

  • Connect forms to a real email or form handler
  • Test submissions
  • Add success and failure behavior if needed

5. Technical Launch Files

  • Create robots.txt
  • Create sitemap.xml
  • Create 404.html

6. SEO Final Pass

  • Review page titles
  • Review meta descriptions
  • Check heading structure
  • Strengthen internal linking
  • Confirm keywords and service wording

7. Responsive And Quality Testing

  • Test desktop layout
  • Test tablet layout
  • Test mobile layout
  • Test buttons, navigation, forms, and dropdowns

8. Deployment

  • Prepare final assets
  • Upload to hosting
  • Test the live website
  • Do a final review before public launch
